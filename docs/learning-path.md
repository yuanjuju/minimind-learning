本仓库的主学习路径已经整理在 [导学页](../guide/00-start.md)。这份清单只记录**下一步真正要补的证据**，不把上游已有功能写成自己的已完成实验。

## 优先级 1：做可比的预训练 / SFT 评估（未做）

1. 自己编写 10–20 条**不依赖实时信息**的固定问题，并给每题标注预期观察点，例如是否遵循格式、是否答非所问、是否完整结束。避免使用训练集原文或挑选模型已经答得漂亮的例子。
2. 固定源码提交、两份权重的哈希、设备、随机种子、`max_new_tokens`、温度、`top_p` 和历史对话设置。预训练与 SFT 使用各自正确的输入模板，不能简单套同一种聊天前缀。
3. 保留每条原始输入和输出，再按提前写好的规则评分。多跑几次以区分采样波动；报告失败例子和局限，而不是只展示最好的一次。

完成后再新增 `evaluation/` 中的脚本与结果；在此之前首页只写“人工观察到 SFT 更像聊天助手”。

## 优先级 2：理解训练效率（未做对照实验）

对照 [`train_pretrain.py`](../trainer/train_pretrain.py) 阅读 batch、梯度累积、保存间隔、续训检查点。若要重租 GPU，先选一个变量和一个问题，例如“batch size 从 32 改成 64，单位样本耗时与显存如何变化”，固定其它配置，并设费用上限。单次 `nvidia-smi` 的显存占用或利用率不能单独证明训练已经最优。

## 优先级 3：选择一个扩展方向（未训练）

[扩展阅读地图](../guide/04-next-topics.md) 提供 LoRA、DPO、MoE、蒸馏与 RL 的源码入口。先明确任务、数据来源和成功指标，再选一项做小实验。没有必要为了让项目“看起来完整”就把所有方向都跑一遍。

以后每次新增实操记录，都按“问题 → 版本/环境 → 数据与许可 → 命令 → 预期 → 原始输出 → 解释与局限”写；这样仓库才会随学习一起成长，而不是凭空扩展完成清单。技术博客是另一项工作，本仓库当前只保存可核对的学习材料。
