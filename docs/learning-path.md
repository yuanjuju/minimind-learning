# 我的 MiniMind 学习路线

本路线以**先理解已有训练，再做小实验**为原则，不要求再次租 GPU。每一步结束时应能用自己的话回答一个问题，而不只是把命令跑通。

## 已完成

- [x] 选择云端单卡 GPU，核对 CUDA/PyTorch、磁盘和模型版本。
- [x] 下载预训练与 SFT 数据，完成 Dense 64M 的两阶段训练。
- [x] 下载并用 SHA-256 核对两个最终权重，在 Mac CPU 上试运行 SFT 推理。
- [x] 用玩具样本比较预训练与 SFT 的 label 掩码：[`learning/`](../learning/)。
- [x] 用临时小模型验证 `loss → backward → optimizer.step` 会改变参数。

## 接下来建议的顺序

1. **读模型结构**：从 [`source-map.md`](source-map.md) 找到 `MiniMindConfig`、`Attention`、`MiniMindBlock` 和 `MiniMindForCausalLM`。检查：为什么输出 logits 的最后一维是词表大小？
2. **做可比评测**：挑选固定的 10–20 条非实时问题，记录提示词、权重类型、`max_new_tokens`、采样参数和原始输出。预训练与 SFT 要用各自正确的输入模板，不能只比较一次随机回答。不要修改或发布训练集原文来“凑”测试集。
3. **研究训练效率**：对照训练脚本弄清 batch、梯度累积、保存间隔和续训状态；若再租 GPU，只做明确目标的小实验，提前设定时间与费用上限。
4. **再看扩展章节**：LoRA、蒸馏、DPO、MoE 和 RL 是可选方向，不必一次全部重训。先能说清它们各自要解决什么问题，再决定哪一条值得动手。

每次实验建议保留一个小记录：问题、固定代码版本、命令/环境、预期、实际结果、结论与局限。第二阶段的技术博客文章会在学习记录稳定后单独撰写，本仓库不会把草稿误当成已经发表的结论。
